# venvs: Reusable Python Environment Profiles

Fast, reproducible Python environments for analytics and exploratory notebook work
without per-project bootstrapping or conda. Each profile is defined declaratively
(no committed virtualenvs) to keep setup lightweight and repeatable.

## Overview

Each environment (profile) directory contains:

- `pyproject.toml`: Dependency and Python version specification
- `uv.lock`: Fully resolved, reproducible lockfile (generated by `uv lock`)
- `.venv/`: Local virtual environment (created by `uv sync`, ignored by Git)

These profiles let you launch notebooks anywhere and attach a consistent kernel.

## Directory Example

```text
ds-core/
ds-ml/
viz-light/
```

## Quick Start

Inside a profile directory:

```bash
uv sync
```

Creates or refreshes `.venv/` from the pinned lockfile.

## Updating Dependencies

Edit `pyproject.toml`, then:

```bash
uv lock      # generate updated lockfile
uv sync      # build environment from lockfile
git add pyproject.toml uv.lock
git commit -m "Update ds-core dependencies"
```

## Register as Jupyter Kernel

```bash
cd ds-core
source .venv/bin/activate
python -m ipykernel install \
  --user \
  --name ds-core \
  --display-name "Python (ds-core)"
```

Repeat for additional profiles; then select the kernel in JupyterLab, VS Code, or
any notebook UI.

## Ad Hoc Notebook Workflow

1. Launch notebooks from any working directory:

  ```bash
  jupyter lab
  ```

1. Pick a shared kernel (e.g. `Python (ds-core)`).
1. Explore / iterate.
1. If the work becomes a project, vendor the environment spec:

  ```bash
  cp ../venvs/ds-core/pyproject.toml .
  cp ../venvs/ds-core/uv.lock .
  uv sync
  ```

  Use the project-local `.venv/` going forward.

## Conventions

- `.venv/` directories are intentionally untracked.
- Do not pip install ad hoc packages into a shared profile; add them to `pyproject.toml`
  and regenerate.
- Keep the profile set minimal to reduce overlap and drift.
- Lockfiles can be platform-sensitive; validate on macOS and Linux if needed.

## Rationale

Provides a conda-like convenience layer with explicit, versioned dependency specifications.
Avoids committing full environments while ensuring fast, reproducible setup for exploratory
analytics and notebook-driven tasks.
